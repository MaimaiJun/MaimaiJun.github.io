    前言

    很久没有更新博客了，机器人工程的毕业生开始学习unity，对比webots软件，它的交互性会更加好，毕竟主要开发的是游戏和CG。
    博主属于无人机方向的研0阶段，分享一下学习的过程。

    一、Unity的部署环境

    &nbsp;&nbsp;&nbsp;&nbsp;博主电脑为10th i5的CPU和GTX1650，系统为Ubuntu20.4，以下内容均为此环境。

    1、安装Unity-hub

    百度或者google搜索后下载后缀为deb的安装包(双系统的电脑默认为amd64/x86）。

        sudo dpkg -i TAB（补全下载好安装包的名字）

    安装完成后在ubunut的application界面找到unityhub并打开，

    hub会推荐你安装最新版（6.0），在ubuntu22.04系统下可以下载安装，但是图形界面有可能不正常（可能需要笔电显卡支持直连）。这里推荐下载他的2022版本，也是ubuntu20.4可以下载运行的版本。

    2、下载Blender

    blender是个可视化3d模型的软件，需要unity3d仿真使用。百度或者google搜索后下载。这里下载后的是个压缩包，解压到系统usr/opt/目录下。

    为了避免后续运行unity遇到blender无法launch的情况，你可以按如下操作：

        当然，您首先必须正确安装 Blender！您应该能够在注销并重新登录后从命令行键入（即，不运行中间命令）。执行此作的简单步骤是：blender
    
    卸载您正在使用的任何其他版本的 Blender，或者sudo apt remove blendersudo snap remove blender
    
    从 Blender 网站下载 Blender tar 文件。
    
    解压存档（我假设是）并将其放入 opt：~/Downloads/blender
    
    sudo mkdir /opt/blender
    
    sudo cp -r ~/Downloads/blender /opt/blender
    
    为您的 Blender 文件创建一个符号链接：
    
    sudo ln -s /opt/blender/blender /usr/local/bin/blender
    
    注意：如果您在创建链接时未能使用 -s 选项，那么您将创建一个硬链接，并在尝试启动 Blender 时收到以下错误：
    此时，您应该能够从命令行启动 Blender。
    
    为您的 blender.desktop 文件创建一个 SYMBOLIC LINK，以便能够将文件与 Blender 相关联：
    sudo ln -s /opt/blender/blender.desktop /usr/share/applications/blender.desktop

    二、Unity基本组件

    1.界面介绍


    这里展示一个简单的demo项目，当你进行新建项目后，大概就会得到一个这样的界面，这里只介绍最主要（重要对于机器人仿真）的部分。其他部分可以通过B站搜索擅码网快速了解。

    1、上图的Hierarchy类型Webots仿真软件的场景树，其中test1就是这个场景的名称，camera和directional light就是场景的运行视角和灯光方向。Plane是常见的地板类型物体。

    2、左下角的区域类型Vscode的工作区，他包含这个Project的所有文件夹。例如Material和Textures管理的是材质包，Model一般是3d模型（主要是blender格式），Prefabs是预制体（当你在环境中创建一个桌子的时候，可以通过不同cube组合，然后保存到这个文件夹，跨场景甚至项目使用，非常方便的一个功能），Scenes场景文件夹（例如右上test1和test2是两个不同的，类似webots的wbt世界文件），Scripts也就是unity的编程语言C#代码储存的地方。

    以上文件夹都可以重新命名，新建Project的时候无这些，这些为Unity玩家通用命名方式。

    3、一些场景交互功能，与主流的3d软件类型，滚轮按键平移，鼠标右键旋转。比较重要的是左上角的Local部分，他代表的是物体的坐标系，需要分清世界坐标 和 局部坐标的关系，在不同的应用场景。

    4、每个物体的设备树详细栏。Transform基本的三维坐标、旋转角度和缩放尺寸。其中，unity的特殊名称和webots仿真不同的地方。Mesh-flitter和Mesh render类似webots的shape-bounding，也就是物体的一个可视化外形。Box collider类型webots的bouding，也就是物理接触的面。最重要的是rigidbody（刚体），他类似webots的physics物理特性，可以看到有质量mass，drag阻力设置，Is kinematic是锁定的意思，可以取消物理特性。

    除此之外，unity的多种joint链接方式需要和webots进行区分，其中固定轴的一些机器人连杆或者机械臂可以用hingjoint，固定无人机桨叶可以用fixed-joint。

    2.关键组件

    1、GameObject

    一个机器人就是由不同的gameobject进行组成的，例如无人机的主体和四个螺旋桨的刚体可以通过四个fixed-joint进行链接。

    在上图中，Doran作为机器人的主要object，他是父级，而MotroXXX和shape原件则是他的子原件。

    在父子级对象中，只要原件没有设置刚体competent功能，那么他和主体中心坐标就会保持一个相对的位置，例如桌子的桌板和桌子的桌腿的相对位置。

    而一旦像无人机机器人进行建模仿真的时候，施加的作用对象可能不在主体上，例如螺旋桨旋转得到的升力作用在螺旋桨一侧 而不是主体，那么为了防止设置刚体的时候，仍然与主体保持相对位置，就需要用到joint组件。

    对于一个无人机，我们需要用到四个fixed-joint，分别对应这四个刚体。

    2、代码模拟机器人传感器原件

    这部分类似于webots的Supervisor监管者功能，在C#代码中获取机器人刚体（也就获取了这个对象的地址,包含Transform的信息）。

    然后通过public进行共享，例如A初始化B类，然后再A的fixedupdate循环中调用B类中的函数getxyz，这样就可以获取到B的位置信息。

    同理，可以让B实时获取A的位置信息，将B当做一个实时更新的GPS硬件设备，当A进行获取时，可以更为精准的模拟传感器。

    public DroneControl vc; // linked externally

    // 引用外部 StateFinder 组件来获取状态信息
public StateFinder2 state;  // StateFinder 用于获取无人机的状态（roll, pitch, yaw, altitude 等）

    在unity的inspect界面互相选择对象后就可以进行共用了，但是这种模拟情况还不太精准，缺少噪声的模拟。

    总结

    以上就是Unity入门的第一章，主要包含无人机模拟部分，具体物体碰撞和外观比较简单，不多记录。
